# 飞书多维表格接入

本应用首版是本机单用户工作台。飞书连接器实际调用官方 OpenAPI；仓库内契约测试使用显式模拟服务，不代表已获得某个企业表的真实权限。未配置 App Secret、目标表和应用权限时，真实读写验收状态为「待外部条件」。

## 新手接入：按这五步操作

这五步在飞书网页和本机工作台完成，不需要把 App Secret 发给 AI。建议先建一个空白测试表，跑通后再连接正式企业库。

1. **创建企业自建应用。** 打开[飞书开发者后台](https://open.feishu.cn/app)，选择所在企业，点击「创建企业自建应用」，名称可填「利明智耀技能库」。进入「凭证与基础信息」，找到 App ID 和 App Secret，暂时保留页面；不用启用机器人或配置事件回调。本项目使用服务端应用身份调用 API。[官方创建与开通权限教程](https://open.feishu.cn/document/introduction-2?lang=zh-CN)
2. **按实际接口开权限。** 依次打开下方七个官方 API 文档，在右侧 API 调试台选择刚建的应用和应用身份 `tenant_access_token`，在「权限配置」里按页面列出的要求勾选并「批量开通」。这样使用的是当前权限清单，不必猜 scope，也不用把全部云文档权限全选。每个接口的权限若写「任选其一」，按企业允许的最小可用项选择。遇到需审批提示，进入应用「版本管理与发布」→「创建版本」→填写版本说明→申请发布，并让企业管理员审批。**发布是否必须取决于权限审核规则：官方教程明确免审权限可以申请后立即生效；需审权限必须发布并审核通过。首次正式接入建议按后台指引完成一次应用发布。**
3. **建表并添加文档应用。** 进入[飞书云文档](https://feishu.cn/drive/home/)，新建→多维表格→空白，名称可填「利明智耀企业技能库」。使用普通数据表，新手测试暂不启用高级权限，也不要选择从其他数据源同步的只读表。按下面的默认表头建 12 列，最后一列改为附件，其余为文本。然后在目标多维表格右上角「…」→「更多」→「添加文档应用」，搜索刚建的应用，授予「可编辑」。API 权限和这张表的文档权限两层都要有；若应用搜索不到，先确认已经开通至少一项多维表格 API 权限，并核对应用发布及可用范围。启用了高级权限的正式企业表还要按实际角色授权，可能需要可管理权限。[官方云文档权限说明](https://www.feishu.cn/hc/zh-CN/articles/360044508113-云文档权限常见问题)
4. **取得表标识，填到本机。** 用浏览器打开刚建的数据表，地址形如 `https://你的企业.feishu.cn/base/APP_TOKEN?table=TABLE_ID&view=...`。`/base/` 后一段是 App Token，`table=` 后一段是 Table ID；它们与开放平台的 App ID 不同。在本机工作台「设置→飞书多维表格」填 App ID、App Secret、表格完整链接和 Table ID，再保存。App Secret 只填本机密码框；不要发到聊天。若复制的是 `/wiki/` 链接，先在飞书打开原始多维表格后复制 `/base/` 链接。[官方参数获取说明](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create)
5. **先只读，再验证写入。** 在本机先点「验证凭证与读取权限」，确认字段兼容；再点「新增测试记录并验证写权限」，核对测试记录已清理。最后选择一项个人技能，在企业库「同步→预览→确认」上传，重复一次应显示无需同步；再从企业库导入并核对完整包里的附属文件。此时才能将对应真实联通验收改为通过。

权限开通所需的七个 API：

| 功能 | 官方 API 文档 |
| --- | --- |
| 验证字段与字段 ID | [列出字段](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-field/list) |
| 读取与去重 | [列出记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/list) |
| 首次上传与独立写测试 | [新增记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create) |
| 同步更新与刷新附件 | [更新记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/update) |
| 清理独立写测试记录 | [删除记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/delete) |
| 上传完整 ZIP 附件 | [上传素材](https://open.feishu.cn/document/server-docs/docs/drive-v1/media/upload_all) |
| 下载及恢复完整 ZIP | [下载素材](https://open.feishu.cn/document/server-docs/docs/drive-v1/media/download) |

可复制的默认表头（列名严格一致）：

```text
Skill ID	名称	简介	分类	标签	状态	来源链接	版本	内容哈希	更新时间	Skill 正文	技能包附件
```

「技能包附件」设为**附件**；另外 11 列都设为**文本/多行文本**。本项目首版的「标签、状态、版本、更新时间、来源链接」也使用文本，不要自行改为多选、数字、日期或超链接字段；否则应改映射或会被兼容性检查拒绝。详细字段约定见下文。

2026-10-26 根据官方入门教程、云文档权限说明和接口参数说明核验以上流程。各企业实际权限名称与免审规则以其开发者后台及 API 文档的「权限配置」为准，不以第三方教程中的旧 scope 列表替代。

## 设置目标与授权

**应用能力补充**：本项目使用“添加文档应用”将企业自建应用加入目标表协作者。按[飞书官方文档协作者说明](https://www.feishu.cn/content/383321056779)，这条授权路径需开启机器人能力：在开发者后台“添加应用能力”添加“机器人”，然后按后台提示发布生效。不需要勾选对外分享，也不需要申请发送消息权限。仅调用创建多维表格API的通用入门教程可显示“应用能力无”，与本项目访问用户已有目标表的授权路径不同。

发布页“权限变更：暂无”只表示本版本未显示新增权限，不能据此判断已获得所有读写权限；请以“权限管理”的实际开通状态及本机连接测试为准。

1. 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用，取得 App ID 和 App Secret，并按后台提示完成权限生效所需的发布/审批或确认免审权限已生效。
2. 给应用申请所需的多维表格读取、记录写入和云文档素材上传下载权限。以接口当前页面列出的权限为准；拥有应用 API 权限后，仍需给应用目标文档的访问权限。测试记录清理还需要删除记录权限。
3. 建立专用的技能多维表格，在飞书中复制原始 `/base/<app_token>?table=<table_id>` 链接。知识库 `/wiki/` 链接请先打开其原始多维表格再复制。可在本地设置页填表格链接，或分别填 App Token、Table ID。
4. 在本地设置中填写 App Secret。不要把密钥粘贴到聊天、技能正文、GitHub issue 或提交记录。密钥仅由后端凭证存储读取；前端配置响应应仅显示已配置状态。
5. 先运行只读连接测试，核对认证、目标表记录读取和逐字段兼容性，再执行写入测试。写入测试创建「【可删除】skill collect 写权限测试」记录，Skill ID 以 `__skill_collect_write_test__` 开头，并尝试删除。若清理失败，会显示具体测试记录 ID；此时需要在飞书人工清理。测试不覆盖已有技能。

默认使用[企业自建应用 tenant_access_token internal 接口](https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal)。配置 `auth_mode=oauth3` 时改用当前[自建应用 tenant_access_token 文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token)列出的 `https://accounts.feishu.cn/oauth/v3/token`，`grant_type=client_credentials`。该文档将返回的 `access_token` 说明为等价于 `tenant_access_token`。这两个模式均是应用身份，不代表每位员工个人权限。访问令牌仅在连接器内存中按实际有效期缓存，不持久化到同步日志。

## 字段映射

可映射到已有表的列。首版使用文本字段存普通元数据，附件字段存完整 ZIP；分类和标签不要求管理员预先建立选择项。没有使用的可选字段可以映射为空字符串。

| 内部字段 | 默认飞书字段名 | 飞书字段类型 | 是否必需 |
| --- | --- | --- | --- |
| skill_id | Skill ID | 文本，type=1 | 是 |
| name | 名称 | 文本，type=1 | 是 |
| description | 简介 | 文本，type=1 | 否 |
| category | 分类 | 文本，type=1 | 否 |
| tags | 标签 | 文本，type=1，逗号分隔 | 否 |
| status | 状态 | 文本，type=1 | 否 |
| source | 来源链接 | 文本，type=1 | 否 |
| version | 版本 | 文本，type=1 | 否 |
| content_hash | 内容哈希 | 文本，type=1 | 否 |
| updated_at | 更新时间 | 文本，type=1 | 否 |
| body | Skill 正文 | 文本，type=1 | 是 |
| package | 技能包附件 | 附件，type=17 | 是 |

映射 JSON 示例：`{"skill_id":"技能唯一标识","name":"技能名称","body":"正文","package":"附件"}`。不同内部字段不能映射到同一列。程序不会创建、删除或修改企业表结构。

正文超过 19000 字符时，表内保存 `[完整正文见技能包附件]` 标记和摘要，完整正文保留在附件。请编辑完整 ZIP 后替换附件，以修改此类长正文。移除标记后，表内正文会被视为用户指定的完整正文覆盖，因此修改前应先备份。

## 手动同步与冲突

进入企业技能库先读记录，或对个人技能运行同步预览。预览是只读操作，会下载实际附件，校验 `manifest.json` 文件清单、大小及每个文件 SHA-256，再计算远端实际字段和文件内容的摘要。程序不只信任表里由应用填写的「内容哈希」「更新时间」。

- 「新增」：没有关联企业记录，可上传完整技能包并新建记录。
- 「上传」：个人内容或元数据变化，企业端相对基线没有变化。
- 「导入」：企业端变化，个人端相对基线没有变化。
- 「冲突」：两端都变化，显示个人正文和企业正文的差异。可保留个人版、保留企业版，或将企业版导入为另一个个人副本。导入副本不会自动上传个人修改。
- 「附件待刷新」：企业直接修改正文后，表内正文与 ZIP 的 `SKILL.md` 暂不一致。普通导入只更新个人副本，保持企业只读，返回 `package_refresh_required=true`；随后预览显示 `refresh_package` 而不是「无需同步」。用户在同步页明确确认后，程序仅更新完整包附件及版本、哈希、更新时间，不改企业名称、状态、来源或其他业务字段。
- 「无需同步」：两端相对上次基线都没有变化，且企业表内正文与完整包正文一致，不新增记录。
- 「附件不可用 / 受阻」：缺包、哈希不匹配、重复 Skill ID、下载权限或字段问题；保留个人技能和日志，修复后重新预览。
- 「远端已移除」：不自动删除个人技能，也不自动重新上传；选择个人版后才明确重建。

每次上传都保存本地 Skill ID、连接 ID、企业记录 ID 和两端基线。创建前按稳定 Skill ID 再查询一次；若创建请求超时，写入意图持久化，下次操作先重新查询。若仍查不到且上次写入结果未知，会阻止盲目新建，避免重复；请等待飞书可见性恢复并重新预览，必要时由维护者核对 `sync_pending` 记录。更新也不盲目自动重试。打包时用短事务锁冻结同一份个人技能版本；上传附件后、更新记录前再次核对企业实际内容摘要，变化时停止并要求重新预览。飞书更新接口未使用原子 compare-and-swap，首版提供的是乐观并发保护，不能保证多人同时修改最后一个请求窗口的强一致性；建议指定单一维护者手动同步。冲突发生时已上传但未关联到记录的素材不会被程序自动删除。读请求仅对限流、暂时服务错误和网络错误有限重试。

选择「保留企业版本」并确认同步时，程序先按企业正文形成个人版本；若企业 ZIP 仍旧，再重新打包并更新原记录附件，返回 `resolved_remote` 与 `package_refreshed=true`。只有显式同步操作才执行该企业写入；普通企业导入、预览和「另建个人副本」不会写企业。企业记录的原始 Skill ID 保持不变，不会被个人副本的新 ID 替换。刷新后，个人正文、飞书正文、完整附件里的 `SKILL.md` 一致，后续预览才显示无需同步。若刷新失败，则保留已导入个人内容和失败日志，并继续显示附件待刷新。

导入包与直接表内编辑的正文合并后形成个人版本，保留企业来源关联。企业填的「已验证」不会赋予个人技能执行验证；实际运行记录仍需在个人库单独登记。不会运行 ZIP 中脚本、不会全局安装 skill、不会自动同步删除。

## 限额与待接入检查

单次技能 ZIP 不超过 20 MiB、解压后不超过 20 MiB、最多 256 个归档条目；附件包必须包含一个 `manifest.json` 与清单中声明的全部文件。单次记录读取上限为 10000 行，分页异常会停止。企业记录必须有且仅有一个完整 ZIP 技能包附件。对有高级权限的表，下载带官方 `bitablePerm` 查询鉴权，关联实际字段 ID、记录 ID 和附件 Token。附件调用与正文调用使用相同连接和应用身份，不开放绕过权限的公开下载地址。

首次真实接入应在专用测试表执行：只读测试 → 明确写测试并核对清理 → 首次上传 → 第二次上传无副本 → 下载恢复脚本与模板 → 修改个人版后更新 → 在飞书直接编辑正文 → 导入 → 两边都改的冲突 → 选择处理并再次预览。将真实测试的目标标识脱敏、实际结果及记录 ID 写入本地验收记录；不把模拟服务通过改写成真实企业联通通过。
