# v0.2.0 抖音原片自动分析与项目关联（预发布）

更新日期：2026-10-29（Asia/Shanghai）。[v0.2.0 独立预发布](https://github.com/baizhanwen/liming-zhiyao-skill-collect/releases/tag/v0.2.0)的标签对应本轮最终文档提交；已验证源码为 `ce8bace700a16c7afab4ce2061d3c793961bb773`。

在工作台粘贴抖音分享链接后，项目自行尝试取得原片，完成音轨转写、抽样画面分析、结构化分析和知识保存。安装脚本提供锁定版本的官方 Chromium；采集不依赖 Codex、系统浏览器登录或人工下载。已有补传和平台摘要任务保留历史身份，不会被当作新原片任务复用。

本轮实际工作台验收：一次提交、一次任务尝试、零上传和零手动重试，取得指定公开源的 **144.8 秒原片**；音画组件完整覆盖后以 FFmpeg stream copy 合并，实际 H.264 视频与 AAC 音轨经 FFprobe 核对。随后 MiniMax 完成 **2 段原音转写、8 张抽样画面分析、文字融合和知识保存**，依据为 `transcript_and_frames`。完整流程约 68.125 秒；原始媒体、转写、回答、配置和截图只留本机私有目录。公开脱敏证据为 [douyin-live-e2e-20261029.json](../artifacts/verification/douyin-live-e2e-20261029.json)。

视频中的项目线索可在同一次文字分析中提取，无额外模型检索请求。明确 GitHub URL 独立核验仓库存在与固定提交；项目名称必须出现在有效来源引文中，名称搜索结果始终为候选，同名歧义、无匹配和限流分别显示。关联失败保留主分析，可单独重查 GitHub。**本次原音转写与 8 张抽样画面中未识别出明确 GitHub 标识，未发起搜索、未强行关联 Easel；真实视频线索到 GitHub 正匹配仍未验证**，正例与错误分支由显式契约覆盖。

采集使用新的匿名 Chromium 上下文与沙箱。强制 CONNECT 代理逐个校验公网地址并固定 IP，浏览器保留原站 TLS 校验，不解密 TLS、不读取已有 profile、不绕登录、验证码或签名。媒体只从当前视频的官方公开元数据和实际响应归属；仅允许播放器增加已核对的 `temp` 缓存键，原签名、水印、重复参数与空值完整保留，下载使用实际观察到的 URL 原串。音频不会因错误的 `video/mp4` MIME 提前被当作原视频，必须核验实际轨道和完整字节覆盖。
