# 技术决策与来源（2026-10-26）

## 0.3.0 项目内二维码与本机会话

使用既有项目Chromium正常渲染抖音官方登录页，读取已定位登录二维码元素的原始data-PNG字节，经有界JSONL内存通道交给后端，再用同源no-store PNG接口展示在工作台。不解码二维码内容，不保存图片到文件或数据库；图片格式、尺寸及大小做有界校验。原候选用元素矩形截图时曾误拍上层短信窗口，已作为真实失败保留，不能继续以矩形截图充当QR。同一登录代次只保持一张原始码；不会自动点击官网刷新或因状态检查重载。同PNG去重，实际失效或官网更换挑战时清图并提示本人在项目重新获取，旧代次/验证中的过期事件被忽略。

账号成功必须同时满足官方self/user-info认证响应与有效认证Cookie。网络未返回证据只是超时，不能伪称平台已撤销会话。登录状态使用Playwright的[storageState机制](https://playwright.dev/docs/auth)，但仅在内存IPC传递，并由既有本机Vault加密，避免官方示例的明文认证文件。系统浏览器profile不导入，Cookie不交给普通HTTP取页、模型、飞书、导出或诊断。分享短链只从原请求的官方HTTPS主文档重定向链确认目标ID，再沿用严格原片采集；不能从推荐内容猜目标。

用户实测在手机确认后出现官网短信身份验证，因此增加同一浏览器会话的官方验证视图，不仿制短信表单、不重放认证API。可见验证时传内存JPEG；本人点击的CSS坐标按缩放回原viewport，临时文字只送当前可编辑焦点，按键只用白名单。服务UUID与Node帧映射、一次消费、图片版本绑定和双边预算防止旧画面/旧请求复用；每次操作后强制新帧，失败只传固定错误。短信发送、验证码内容与验证题目均由本人选择和操作。截图返回后再检查验证仍可见；离开验证时销毁帧并重新求取官方认证证明，防止用验证前的旧profile结束登录。

短信输入步骤可能不再出现初始“身份验证”标题。首次检测到该步骤后跟踪实际官网验证根/遮罩的生命周期，服务也锁存当前验证阶段，迟到的扫码/检查进度或QR不能使界面退回扫码。验证根仍存在时不得重建挑战；根替换或状态不明时保守保持验证。完成后求证使用同context的新页面，用户的验证输入页不被导航或刷新。

## 初版决策与来源

采用施工书推荐栈。锁定的实际版本见 `uv.lock`、`requirements.txt` 和 `frontend/package-lock.json`，而非依赖本文猜测最新版。

- 本机系统 Python3.9 不满足，使用已安装的 Python3.12.14 隔离环境；发布要求 Python3.11+。
- [FastAPI 发布记录](https://fastapi.tiangolo.com/release-notes/) 核对后解析到0.162.0；后端不使用实验分布式队列。
- [Vite 官方入门](https://vite.dev/guide/) 要求 Node20.19+/22.12+；本机Node24.19.0。
- [React 官方版本](https://react.dev/versions) 与 npm registry 确认稳定包，再锁实际安装结果。
- [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 核对 messages/image_url/response_format；采用兼容协议而非保证所有厂商相同能力。提供 JSON mode 开关。
- [Transcriptions](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create) 核对 multipart file、model、json text；每120秒音频分段，保留段起点。默认20分钟/100MB。
- [GitHub REST 搜索](https://docs.github.com/en/rest/search/search) 有 Token 时代码搜索，无 Token 时真实仓库搜索并标降级。
- 抖音只读取公共分享页的明确媒体地址，经每次解析/重定向公共IP检查和连接IP固定；不绕登录和反爬，不依赖计费解析服务。官方授权接口并非任意公开视频下载 API。
- [Easel 展示](https://zjureal.com/Easel/) 只参考浅色、留白和工作台信息层次；没有复制其源码、图片、商标和设计素材。来源分析固定版本单列保存，不执行该仓库脚本。

凭证使用 Fernet 加密，与SQLite分离；本机密钥文件限制权限。它防止凭证出现在数据库/普通备份中，不保护已被同一系统账户控制的主机。普通备份不含密钥和密文，恢复后需重配凭证。

## v0.1.1 真实联通后修正

- 匿名GitHub API耗尽时，仓库快照改走受限的公开Git对象读取；禁用系统/全局Git配置、凭证助手、netrc、hooks、重定向、子模块与懒取。没有checkout，不执行仓库脚本。总时间75秒、目录128MiB、单文字blob512KiB、文件与输出另有限额。搜索与技能发现API的限额仍如实报告，不以样例替代。缺Git时在诊断中提示。
- [DeepSeek当前Chat接口](https://api-docs.deepseek.com/api/create-chat-completion/)默认启用推理且默认high effort。对精确官方host的有上限结构化提取，应用默认关闭推理，允许用户在高级设置改回；其他厂商不添加该私有参数。JSON例子和有界正文修正后，已在用户自配服务真实完成Easel分析与追问。输出仍遵守128—6000配置上限，遇finish_reason=length不会在同上限下盲目重复。
- 提示词版本升级v2并记录实际消息哈希。失败回答、实际使用量、finish_reason与校验原因保存为本机model_runs诊断，不保存供应商推理过程，不写服务日志或技能导出；私人资料备份会包含这些诊断。界面按需读取原回答，不为查看诊断再次调用模型。
- 生成的草稿区分“来源有操作流程但尚未运行”与“只有观点、不适合生成操作技能”。按[Agent Skills格式](https://agentskills.io/specification)为新生成内容补齐name/description YAML，导入第三方正文保持原样；导出目录优先匹配正文中的有效name。正文仍为草稿，不执行其中命令。
- 企业表直接改正文后，旧ZIP不能被判为已一致：普通导入只读，显式同步再刷新完整包。保留企业稳定Skill ID，刷新后核对个人正文、表内正文与ZIP正文一致。企业转存保留上游来源链。
- 实测即时重启暴露TIME_WAIT误判，端口检查先辨识监听者，再按POSIX地址复用语义试绑；Windows仍用独占绑定。不会结束占用端口的其他进程。
