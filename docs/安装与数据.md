# 安装、启动、诊断与资料保护

应用只在本机回环地址提供单用户服务。后端提供已构建前端，正常使用只启动一个进程。安装不需要模型、GitHub 或飞书凭证；涉及外部服务的操作仍需在设置中单独配置、测试。

## 运行时

- Python 3.11 或更高版本：[官方安装](https://www.python.org/downloads/)。推荐 3.12。
- Node.js 20.19+（20 系列）、22.12+（22 系列）或更新受支持版本；推荐 [Node.js 24 LTS](https://nodejs.org/)。Node 21 不符合 Vite 8 的官方 engines 约束。
- 可选 [uv](https://docs.astral.sh/uv/getting-started/installation/)，用于 `uv.lock` 精确安装。没有 uv 时脚本使用项目虚拟环境与锁定的 `requirements.txt`。
- 视频/音频处理需要 [FFmpeg 和 FFprobe](https://ffmpeg.org/download.html)。缺少时文字、字幕和技能库仍可使用；诊断显示媒体能力受限。
- Windows 推荐 [PowerShell 7](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows)。CI 使用 `pwsh`，实际目标系统通过状态以验收报告为准。
- 匿名公开页采集使用项目锁定的 Node.js Playwright 和配套 Chromium。`setup` 自动从 Playwright 官方下载源安装浏览器到当前用户缓存，不需要 Codex、系统 Chrome 或任何已有浏览器登录。Node.js 在应用运行期间也需要保留。

脚本只安装锁定的项目依赖，不下载或执行未知运行时安装命令。缺少 Python/Node.js 时退出并给出官方来源。`npm ci --include=dev` 保证即使设置了 `NODE_ENV=production`，构建工具和锁定的采集运行时仍会安装；pip/uv 使用锁文件。浏览器由锁内 Playwright CLI 安装，不通过 `npx` 临时获取其他版本。应用导入的第三方 skill 不会被这些脚本自动安装或运行。

## 首次安装与启动

macOS / Linux：

```sh
cd /path/to/liming-zhiyao-skill-collect
bash scripts/setup.sh
bash scripts/start.sh
```

Windows PowerShell：

```powershell
Set-Location 'C:\path\to\liming-zhiyao-skill-collect'
pwsh -File scripts/setup.ps1
pwsh -File scripts/start.ps1
```

打开 `http://127.0.0.1:8765`。启动保持前台运行，按 Ctrl+C 停止；日志追加到 `data/logs/server.log`。脚本检查端口，无权自动结束占用它的其他进程。所有服务默认监听本机，不能靠更改监听地址把当前应用直接当多用户服务使用。

安装脚本可重复执行，不覆盖现有数据库、模型配置或凭证；前端构建产物会按当前源码重建。脚本检查已有 Python，也可用 uv 发现已安装的合适解释器；不会静默下载 Python。首次安装仍需要联网下载锁定依赖。

Chromium 首次下载需要额外磁盘空间和到官方 CDN 的网络，重复安装复用相同版本缓存。安装器仅对子进程清除 Playwright 下载镜像地址覆盖，使用锁内默认官方来源，不改用户全局环境。需要自定义缓存目录时，可在安装和启动时一致设置 Playwright 官方支持的 `PLAYWRIGHT_BROWSERS_PATH`；不要指向已有用户浏览器 profile。采集使用新的临时匿名上下文，不读取用户 Cookie 或其他应用登录。

安装器不执行 `sudo`、`apt` 或 `--with-deps`，不会自动改变系统库。Linux 若缺少浏览器依赖库，应按 [Playwright 官方系统要求](https://playwright.dev/docs/browsers#install-system-dependencies) 由系统管理者准备后重跑安装。缺少浏览器时诊断明确标记“匿名原片采集”环境未完成；文字和 GitHub 功能仍可启动。浏览器文件存在、启动成功或页面打开均不等于已获取和分析原片，具体视频仍须保留下载、媒体、转写与模型证据。

## 配置数据目录和端口

macOS / Linux：

```sh
SKILL_COLLECT_DATA='/absolute/private-data' SKILL_COLLECT_PORT=8766 bash scripts/start.sh
```

Windows：

```powershell
$env:SKILL_COLLECT_DATA = 'D:\private-data'
$env:SKILL_COLLECT_PORT = '8766'
pwsh -File scripts/start.ps1
```

环境变量由启动进程继承。`.env.example` 只是说明模板，脚本不会自动 `source` 任意 `.env` 文件；推荐在本地设置页配置服务。端口允许 1024—65535。数据目录应位于私人本机磁盘，避免放进公开仓库、共享同步目录或第三方 skill 目录。

## 本地诊断

```sh
.venv/bin/python scripts/doctor.py
.venv/bin/python scripts/doctor.py --json
```

Windows 对应 `.venv\Scripts\python.exe scripts/doctor.py --json`。诊断检查 Python/依赖、Node、项目 Playwright/配套 Chromium 文件、前端构建、FFmpeg/FFprobe 和 SQLite 完整性，不读取或输出凭证文件，不启动浏览器、不调用外部服务。Chromium 文件检查不能证明系统依赖库完整或网站可获取。启动脚本只检查端口，不会因缺少浏览器阻止文字/GitHub功能。诊断通过不代表模型、GitHub、抖音或飞书已联通，连接测试和业务验收需另做。

## 数据目录与凭证

默认 `data/`，主要包含：

| 路径 | 内容 |
| --- | --- |
| `app.sqlite3` | 知识、技能及版本、任务、来源、设置元信息与同步日志 |
| `uploads/` | 用户补充的视频、音频、字幕 |
| `tasks/` | 来源材料、分段音频、关键帧和处理结果 |
| `logs/server.log` | 服务运行日志 |
| `.secrets.key`、`secrets.enc` | 分离于数据库的本机加密密钥与加密凭证 |

凭证只保存在后端本机。数据库、技能包和备份均不含该凭证文件；迁移后须重新输入密钥、Token 和飞书 Secret。`data/`、`backups/`、`.env`、私有验收材料默认排除出 Git。加密文件与密钥同属本机用户权限边界，不等同于企业级密钥隔离。

## 备份与恢复

备份包含私人知识、媒体和企业技能，不能发布到 GitHub。建议停止正在处理材料的任务后备份，以便所有媒体检查点完整。数据库使用 SQLite backup API，可正确包含 WAL 中已提交的数据；只包含 `app.sqlite3`、`tasks/`、`uploads/`，排除凭证、日志和锁。

```sh
.venv/bin/python scripts/backup.py backup --output backups/private-2026-10-26.zip
.venv/bin/python scripts/backup.py restore backups/private-2026-10-26.zip --target /absolute/new-private-data
SKILL_COLLECT_DATA=/absolute/new-private-data bash scripts/start.sh
```

Windows 用 `.venv\Scripts\python.exe` 调用同一 Python 脚本，并通过 `$env:SKILL_COLLECT_DATA` 选择新目录。恢复目标必须不存在或为空；绝不合并覆盖已有资料目录。旧目录先保留，确认新目录的资料和凭证均正常后再由用户决定清理。

恢复会验证清单、哈希、条目数、压缩比例、SQLite 完整性与文件路径；拒绝目录穿越、符号链接、清单外文件、凭证和不允许的路径。上限为单文件 128 MiB、总资料 512 MiB、5000 个文件。超限时拆分或外部妥善保存原数据，不假称备份成功。

恢复会把媒体引用重映射到新数据目录。原来的运行中/排队任务变成“待配置”，不会恢复后自动向外部模型发送材料。检查和重新测试模型、GitHub、飞书连接后，再手动继续任务。连接历史测试标识会清除；完成的知识和技能记录保留。

## 升级

1. 停止服务，创建新文件名的备份，保留当前可运行版本。
2. 阅读新版本说明；工作区有个人改动时先保存，禁止无检查执行 `git reset --hard`。
3. 更新源码后重新运行 `setup.sh` / `setup.ps1`，锁定依赖和前端随源码更新。数据库迁移以版本记录方式维护。
4. 运行诊断，启动后检查知识/技能数量、版本和媒体引用。分别测试需要使用的外部连接。
5. 出现问题时使用旧源码和备份恢复到一个新空目录，不直接覆盖现有资料。

`uv.lock` 是开发锁；`requirements.txt` 是无 uv 安装的固定版本导出。更新 Python 依赖时必须一并刷新：

```sh
uv lock
uv export --frozen --no-dev --no-hashes --no-emit-project --format requirements-txt --output-file requirements.txt
```

前端依赖由 `frontend/package-lock.json` 锁定。CI 对 Ubuntu/macOS/Windows 运行核心契约测试与实际安装构建；只有具体工作流成功后，相应平台才可写“通过”。
