# 抖音原片获取、分析与 GitHub 项目关联

本功能由「利明智耀.skill clloect」项目自身运行。用户在本地工作台粘贴分享链接后，应用自动尝试取得原片、处理音画、调用已配置的模型并保存结果，**不需要安装或运行 Codex，不需要 AI 助手代为下载，也不依赖用户已有浏览器登录**。

“自动”不等于绕过平台限制。0.3.0支持在项目内打开官方窗口扫码，保存并复用已验证会话；验证码和安全验证由用户在官方窗口完成。即使已登录，私密权限、失效链接、地域或平台限制仍可能阻止获取；任务保留实际失败阶段，不会用标题、平台 AI 摘要或其他视频填充成功结果。

## 安装与使用

原片分析需要 Python、Node.js、项目配套 Chromium，以及 FFmpeg/FFprobe。模型服务由用户在本地“设置与诊断”中配置，文字、视觉、转写分别检查；密钥不应发到聊天或写进代码。模型请求使用当前配置的服务，实际用量按供应商规则计算。

在项目目录安装、启动：

macOS / Linux：

```sh
bash scripts/setup.sh
bash scripts/start.sh
```

Windows PowerShell 7：

```powershell
pwsh -File scripts/setup.ps1
pwsh -File scripts/start.ps1
```

`setup` 安装锁定的项目依赖及官方配套 Chromium。它使用独立浏览器运行时，不要求系统 Chrome，也不会读取已有浏览器 profile、Cookie 或其他应用登录。Node.js 在日常运行期间仍然需要保留。系统运行时、FFmpeg 和 Linux 浏览器系统库的准备方式见[安装与数据](安装与数据.md)。

使用步骤：

1. 打开默认入口 `http://127.0.0.1:8765`；自定义端口以实际启动配置为准。
2. 在“设置与诊断”配置文字、视觉与转写服务，分别测试对应能力。
3. 在工作台粘贴完整抖音分享文本或链接，选择分析深度后提交。
4. 打开任务查看来源获取、媒体处理、转写、画面分析、内容分析、GitHub 关联和保存阶段。
5. 阅读带材料引用的分析及知识卡片；需要积累为 Skill 时再生成草稿。生成或导入不自动授予“已执行验证”。

不需要用户先补传视频来完成这条自动流程。文件上传与字幕输入是另外的输入能力，不能用它们的成功替代某条分享链接的原片自动获取结果。

### 在项目内扫码连接（0.3.0）

1. 打开“设置与诊断 → 来源与团队连接 → 抖音登录与连接”，点击“扫码登录抖音”。
2. 项目从独立 Chromium 内正常渲染的官网获取二维码图片，在工作台卡片里展示。用手机抖音App内的“扫一扫”扫描卡片中的二维码，并在手机确认。项目会单独显示“已扫码，等待手机确认”，检查状态不重新加载或更换当前挑战。不要把验证码、Cookie或密钥发给助手。

二维码离开扫码步骤后，若官网还未确认登录，卡片会显示“官网登录提示”及同一官网的当前画面，供本人继续操作；明确的身份验证使用“官方验证视图”。两者都不代表已登录。二维码失效后只提示本人点击“重新获取二维码”，不会自动换码。
3. 等待工作台显示“抖音会话已验证”；必要时点击“检查登录状态”。项目必须收到官方账户认证响应，单有 Cookie 或页面打开不会显示已验证。
4. 回到工作台粘贴分享文字即可分析。旧失败任务请点击“重试/继续”；登录本身不触发模型收费请求。
5. 可用“检查已保存会话”向官网重新核验，或“退出并清除本机会话”移除本机登录状态。清除会停止当前抖音采集；已保存的媒体和知识不删除。平台会话可能提前失效，需要重新扫码。

### 官网要求额外身份验证时

新设备、账号或平台风控可能在手机确认之后要求身份验证。本机实测已遇到官网提供“接收短信验证码”和“发送短信验证”的情况；手机确认不等于官网已签发有效会话。

工作台的“官方验证视图”显示同一浏览器会话的当前官网画面。由本人点击官网选项；需要输入时，先在画面中点对应输入框，再使用旁边的临时输入控件转送内容。输入发出后立即清空；需要按键可使用Enter、Tab或退格。画面可适应宽度或放大后滚动查看，每次操作后等待新画面，避免重复提交。刷新画面仅重新查看，不重新加载官网、发送短信或重建登录挑战。

助手不会点击短信发送、填写或求解验证码。临时输入仅经本机后端与内存通道转送到当前官网输入框，不保存到数据库、凭证库、日志、模型或备份；不要发到聊天。官网画面也仅在当前验证内存中保留，验证结束、取消或登录成功后移除。该视图是官网实时渲染的画面与本人操作转送，不是仿制短信表单或另一套认证接口。

扫码窗口由运行后端的电脑打开，适用于有桌面环境的本机安装。客户 Win11 不需要安装 Codex，也不用打开系统抖音客户端或手工导出 Cookie；无桌面显示的远程服务器不具备该扫码窗口条件。程序不会导入系统浏览器/抖音客户端的登录状态。

二维码读取官网实际图片的原始PNG，不自编、不解码或生成替代登录地址，也不以可能被验证弹层覆盖的矩形截图充当QR。图片仅保留在当前登录内存中，以同源、不缓存的本机接口显示；取消、结束或清除时销毁，不进入数据库、日志、备份或公开截图。登录存储只经内存通道交给项目专属浏览器，并加密保存在 `secrets.enc`。业务数据库仅存状态、核验时间及完整性摘要；前端、模型、企业表、备份和公开诊断不含会话。不要复制凭证文件给客户，客户在自己的电脑重新扫码。

## 项目如何取得原片

处理顺序如下：

| 阶段 | 实际处理 |
| --- | --- |
| 分享页解析 | 默认静态获取；获取失败且尚无目标ID时，项目浏览器核对原始主文档官方HTTPS跳转链。只从请求链中的视频路径识别目标，不借用推荐卡片、标题或页面任意ID |
| 临时浏览器 | 未连接时使用新的匿名 Chromium；连接后仅在项目新会话中恢复已核验登录，不经过匿名静态请求传递 Cookie |
| 媒体归属 | 由官方来源响应中匹配的视频 ID 绑定媒体地址；同页推荐视频与所有 `video` 元素不会被直接当作目标原片 |
| 完整下载 | 使用实际观察到的媒体地址及当次匿名访问上下文，核对完整文件或 Range 分段的字节覆盖范围与 SHA-256 |
| 轨道检查 | 用本地 FFprobe 检查真实视频轨、音轨和时长；服务器标记 `video/mp4` 本身不证明有视频轨 |
| 本地合并 | 平台返回 DASH 分离音画时，只对同一视频、完整且时长相容的轨道进行本地 stream-copy 合并，不重新编码 |
| 进入分析 | 验证后的本地媒体才进入音频分段、抽帧、模型分析和知识保存 |

来源记录保留原分享链接、规范视频链接、视频标识、获取方法、媒体哈希和实际媒体信息。采集阶段默认最多 180 秒；后续模型处理有独立阶段，不能把它理解为整项分析必须在 180 秒内结束。视频仍受 100MB、20 分钟的应用上限约束。

### 网络与会话隔离

浏览器使用项目内的本地 CONNECT 代理。代理只接受无凭证 authority 的 443 端口请求，先校验解析结果为公网地址，再直接连接已校验的数字 IP；Chromium 自己验证原站 HTTPS 证书，代理不解密或替换 TLS。

浏览器被强制使用代理，并关闭隐式回环绕过、直接 DNS、QUIC、非代理 WebRTC UDP、Service Worker 与 WebSocket 通道。连接数、活动连接、资源大小、总流量、取消和截止时间均有边界。私网、回环、保留地址或混合地址结果不会被作为正常来源放行。

当系统 DNS 仅返回 `198.18.0.0/15` FakeIP 时，应用使用固定官方 DoH 端点取得并重新校验公网地址，仍保留 HTTPS、Host/SNI 和 IP 固定连接；不修改用户的代理或系统 DNS 配置，不通过关闭安全检查解决问题。

应用不自行破解平台签名、验证码或登录限制，也不注入反检测脚本。只使用正常官方页面产生的访问。当前兼容实际观察到的两种额外参数组合：仅 `temp`，或 `temp` 与单值 `__vid`；后者必须逐字等于请求的视频 ID。仅在 HTTPS、主机、端口、路径相同，且官方发布地址的全部原查询参数和值——包括重复值和空值——保持不变时才关联媒体。额外 ID 本身不能建立媒体归属，其他未知组合仍拒绝。下载使用完整的实际观察地址，不删签名、不改水印参数、不拼接替代地址。

当次匿名访客会话仅供该次采集使用；用户扫码会话按上述规则在本机加密保存。Cookie、完整签名媒体地址和请求头不进入业务来源记录或公开证据；临时响应缓存用于进程间处理后清理，完整媒体与处理产物保存在本机私人资料目录。来源中 `session_used` 仅表示该次采集恢复了项目会话，不证明登录在平台上持续有效或原片已经获取成功。

## 分析依据与 GitHub 关联

音轨按最多 120 秒一段处理。快速模式取 4 张画面，深入模式取 8 张；抽帧结果携带取样时间。转写与视觉服务分别处理实际材料，再由文字服务形成带证据引用的分析。

音频转写不是逐字准确保证，八张抽样帧也不等于连续观看了每一帧。文字或画面没有明确出现的内容不能补成事实。没有视觉或转写配置时，任务会显示对应限制或待配置状态，不会产生假成功。

分析完成后，项目会根据保存的材料自动识别、核验或检索 GitHub 线索：

| 材料中的线索 | 处理与结果边界 |
| --- | --- |
| 明确 GitHub 地址 | 核验来源写出的仓库存在及提交，保留材料引用；仓库存在不自动证明视频与该仓库完全对应 |
| 有证据的项目名称 | 使用可回溯到转写或抽样画面的名称进行有界搜索，展示候选和歧义；即使只有一个结果也不自动确认同一项目 |
| 没有明确线索 | 明确显示未形成可关联线索，不凭 Claude、Codex 等普通产品名猜测仓库 |
| GitHub 请求受限 | 显示认证、限流、网络等实际错误；保留视频分析，不把检索错误写成“项目不存在” |

可以在关联面板使用“重新检索项目”，只重新查询 GitHub，不重复调用转写、视觉或文字模型。点击“分析此仓库”或“分析此候选仓库”才创建独立仓库分析任务；读取会保存实际来源版本，不执行仓库代码。

## 常见受限情况

### 客户机短链接访问诊断

客户机显示 `douyin_fetch`、没有完整页面响应而无法继续时，可使用独立的 `scripts/diagnose_douyin.py`。它兼容已安装的0.2.2，通过应用同样的公网校验/IP固定连接、User-Agent、Cookie移除和最多5次跳转方式访问分享页，并额外将每一跳限制为官方平台HTTPS页面、在读取正文前拒绝媒体类型。它不启动浏览器、不走原片下载或模型分析、不读取应用凭证、不访问数据库，也不使用个人浏览器登录。

在项目根目录运行（将示例URL替换成实际分享链接）：

```powershell
.\.venv\Scripts\python.exe scripts\diagnose_douyin.py --url "https://v.douyin.com/YOUR_SHARE_ID/"
```

macOS/Linux用 `.venv/bin/python scripts/diagnose_douyin.py --url "https://v.douyin.com/YOUR_SHARE_ID/"`。已有0.2.2客户可单独将该脚本保存到项目的 `scripts` 文件夹；历史0.2.2发行包不包含后续新增脚本，原标签不移动。

将输出JSON交给维护者，重点查看：

- `network.category`：区分DNS、公网地址保护、TLS、HTTP状态、连接、超时或跳转等失败；不会将403直接判定为必须登录。
- `origin_request_attempts` 与 `hops`：计量实际尝试和响应状态；只输出状态码与布尔信息，不包含URL、视频ID、IP、请求头或响应正文。
- `platform_redirect_has_video_id`：只表示某次平台跳转URL含数字视频ID，不等于已验证官方媒体归属或取得原片。
- `runtime`、`ffmpeg_found`、`ffprobe_found`：浏览器文件及媒体运行条件。`--check-runtime`不启动浏览器；文件存在不代表原片业务联通。

网络由独立子进程执行，40秒硬等待上限后终止并回收；运行时检查另有10秒上限。子进程日志、异常消息、运行时路径和未知字段不透传，只重建白名单报告。TLS问题需检查证书和网络环境，诊断不会关闭证书验证。只读诊断成功不能替代该客户机上的完整原片与模型验收。

| 现象 | 检查方式 |
| --- | --- |
| Chromium 未安装或无法启动 | 重新运行项目 `setup`，核对官方浏览器下载源网络；Linux 按官方要求准备系统库，安装器不会自动提权安装 |
| 缺少 FFmpeg/FFprobe | 按[安装说明](安装与数据.md)准备官方工具后重试；浏览器取得文件不代表音画处理已完成 |
| 需要登录、验证码、私密权限或其他访问条件 | 任务记录实际受限阶段；应用不读取个人浏览器登录，也不突破访问条件 |
| 只有标题、摘要、播放器或首个 Range 片段 | 不算原片获取成功，必须具备同一目标的完整媒体、字节覆盖、哈希和轨道验证 |
| 原片已取得，但模型阶段失败 | 查看对应转写、视觉或文字阶段的配置、网络、配额与供应商错误，不重复把“浏览器可播放”当作分析成功 |
